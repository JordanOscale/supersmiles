# Super Smiles → GoHighLevel export

Generated by `tools/build-ghl-export.py`. Re-run it after any change to
`super-smiles-website/` — **never hand-edit the files in here**, they get
wiped on the next build.

```
python3 tools/build-ghl-export.py
```

Every file is **body markup only** — no `<!DOCTYPE>`, `<html>`, `<head>` or
`<body>`. Each one goes into a single full-width Custom Code / HTML element on
its blank GHL page.

**07 and 08 are two states of `/book`, but they can't share a slug.** GHL
won't allow two pages at the same path, and an unpublished page keeps its path
so its redirect keeps working. So while bookings are closed, 07 sits at `/book`
(published), and 08 sits at `/book-open` (unpublished, redirecting to `/book`
so nobody can reach the booking widget early). The two swap when the gate
opens — see **The booking gate** below. All other slugs must match this list
exactly or the nav and footer links break. Every internal link is
extensionless (`/about`, not `/about.html`).

The 12 pages each carry their own nav, footer and announcement ticker, same as
the static site. Changing the nav means re-running the build and re-pasting all
12, so make nav changes in `super-smiles-website/` first.

## Which set to use

**`pages/` — use this one.** Lean markup. The CSS and JS live once in the
site-wide settings, so a style fix is one paste instead of twelve.

Three one-time pastes first:

1. `SETUP-1-head-code.html` → Site Settings ▸ Tracking Code ▸ **Head**
   (Google Fonts + the booking-gate switch)
2. `SETUP-2-custom-css.css` → Site Settings ▸ **Custom CSS**
   (all of `styles.css` + a GHL wrapper-reset block)
3. `SETUP-3-footer-code.html` → Site Settings ▸ Tracking Code ▸ **Body/Footer**
   (LeadConnector `form_embed.js` + all of `app.js`)

**`pages-standalone/` — fallback.** Same markup with the fonts, CSS, gate
script and JS inlined into every page. Use it only if the tracking-code fields
aren't available on the plan, or if a page won't pick up the site-wide CSS.
Each file is ~80KB, and a style change means re-pasting all 12.

Don't mix the two sets — a standalone page plus the site-wide footer code runs
`app.js` twice, which doubles the ticker and every click handler.

## The booking gate

The static site has one switch (`BOOKINGS_OPEN` in `assets/gate-config.js`).
In GHL it lives in the head tracking code (`SETUP-1-head-code.html`) and drives:

- the announcement ticker on every page
- **every `/book` button label on every page.** Each button carries both
  labels (`<span data-when="closed">Join Waitlist</span><span
  data-when="open">Book free consultation</span>`), and CSS shows the one
  that matches the gate. **Opening or closing bookings never requires
  rebuilding or re-pasting any page.**

Pages 07 and 08 also stamp their own state at the very top of their markup,
so `/book` is always self-consistent, whichever order you do the steps in.

### One-time setup (while closed)

1. Page **07** (waitlist): slug `book`, **published**.
2. Page **08** (booking): slug `book-open`. Build it, then **Unpublish** it
   (page ▸ Options ▸ Unpublish) with its redirect pointing at `/book`.
3. **Test it:** visit `/book-open` and confirm it redirects, and confirm
   `/book` still loads the waitlist.
4. **Disable the GHL calendar** behind the booking widget as well.
   Unpublishing page 08 doesn't stop anyone who has the direct widget link
   (`book.supersmiles.au/widget/booking/…`) from booking.

### To OPEN bookings

Do this at a quiet time. Between steps 2 and 4, `/book` briefly returns a 404.

1. Head tracking code: set `var BOOKINGS_OPEN = true;` and save.
2. Rename page 07's slug from `book` to `book-closed`.
3. Rename page 08's slug from `book-open` to `book`.
4. Publish page 08, then unpublish page 07 (redirect → `/book`).
5. Re-enable the GHL calendar.

### To CLOSE bookings again

The same steps in reverse: set `BOOKINGS_OPEN = false`, rename 08 → `book-open`,
rename 07 → `book`, publish 07, unpublish 08 (redirect → `/book`), and disable
the calendar.

**Don't** redirect `/book` → `/book-open` as a shortcut. GHL redirects are
permanent (SEO-style). Browsers cache them, so switching back later can trap
returning visitors in a redirect loop.

### CTA labels

The labels are the exact pre-waitlist strings (commit `236f942`), not new copy:

| Button | Closed | Open |
|---|---|---|
| Nav (desktop + mobile menu) | Join Waitlist | Book free consultation |
| In-page CTA sections | Join Waitlist | Book your free consultation |
| Bottom CTA bands | Join Waitlist | Book a free call |
| Sticky mobile bar | Join Waitlist | Book free call |

The 11 plain-text footer links read "Book a free call" in both states.

## Known caveats

- **Images are served from Vercel.** Relative paths like `assets/hero.jpg`
  can't survive the move, so all of them now point at
  `https://supersmiles-jordan-os-projects.vercel.app/assets/...`. They work
  immediately, but it's a cross-origin dependency on the Vercel project
  staying up. To move them into GHL's media library, upload the files and
  find/replace that one base URL. `ASSET_BASE` at the top of the build script
  is the single place to change it.
- **OG / Twitter images** were pointing at `www.supersmiles.au`, which
  currently serves a *different* site, so they've been repointed at Vercel too.
  Once `supersmiles.au` is actually served by GHL, repoint them at the real
  domain — social scrapers want an absolute URL on the canonical host.
- **Full-bleed sections.** The ticker, dark bands and footer run edge to edge.
  Set each GHL section holding this code to full-width with zero row/column
  padding. The `GHL COMPATIBILITY` block at the bottom of the CSS tries to
  force this, but the builder setting is the real fix.
- **Sticky nav** (`position:sticky`) breaks if any GHL wrapper has
  `overflow:hidden`. The compat block sets `overflow:visible` on the known
  wrapper classes; if the nav still doesn't pin, that's the thing to hunt.
- **SEO title, meta description, OG image and canonical** can't live in a
  Custom Code element. Each file's opening comment lists its values — paste
  them into that page's GHL settings.
- **Page-transition fade.** `app.js` intercepts internal link clicks and
  navigates via `window.location.href` after 130ms. Harmless in GHL, but it's
  why links feel slightly delayed.
- The `.mobile-cta` bar in the markup is dead — `styles.css` hides it sitewide
  with `display:none !important`. Left in place to match the source.
